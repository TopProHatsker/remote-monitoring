# PC Monitor: состояние проекта

Обновлено 13 ноября 2026 года. Репозиторий:
[TopProHatsker/remote-monitoring](https://github.com/TopProHatsker/remote-monitoring), ветка `master`.

## Реализовано

Мониторинг Linux-хоста через Node Exporter и Prometheus. FastAPI отдаёт сайт,
каталог обнаруженных показателей, текущие значения, историю и `/health`.
Клиент написан на TypeScript/Vite с GridStack и uPlot. CPU, RAM, swap,
файловые системы, дисковый ввод-вывод, сетевые интерфейсы и доступные температуры
выбираются из каталога. На тестовом ASUS обнаружены 38 показателей.

Можно создавать числовые карточки, шкалы и графики с одним или двумя
совместимыми рядами. Доступны название, источник, цвет, порог предупреждения,
перемещение, изменение размеров и удаление. У шкалы и графика текущее
показание находится справа от названия; графику отдана большая часть карточки.

Светлая и тёмная темы используют палитру и геометрию «Витрины».
На верхней панели остаются имя машины, состояние связи, управление карточками,
тема, полный экран и размер поля в клетках. Логотип, слоган и общий футер удалены.

## Поле и сохранение

Ширина и высота поля задаются в клетках и применяются автоматически,
без кнопки подтверждения. Число колонок — от 2 до 48, строк — от 2 до 96.
Карточки привязаны к одной фиксированной сетке. Под экран масштабируется поле
целиком; смена ориентации и вход в полный экран не меняют координаты и размеры
карточек в клетках. Уменьшение с обрезанием существующих карточек отклоняется.
При нехватке места для новой карточки интерфейс предлагает увеличить поле.

Настройки хранятся в браузере для данного адреса сайта:
`pc-monitor-board-v1` содержит формат `version: 2` с полями
`widgets`, `columns`, `rows`, `layout`. Прежние раскладки переносятся
с резервной копией в `pc-monitor-board-before-fixed-grid`.
Выбор темы находится в `pc-monitor-theme`. Автоматической синхронизации
между браузерами и устройствами нет.

## Запуск и данные

Команды запуска и проверки — в [README.md](README.md).
На ASUS сайт запущен по адресу `http://192.168.1.34:8080` через
`MONITOR_BIND=192.168.1.34 docker compose -f compose.yaml up -d --build`.
Это адрес локального тестового стенда, он не зашит в исходники клиента.

Compose поднимает `app`, `prometheus`, `node-exporter`. У приложения опубликован
порт 8080; Prometheus не публикует 9090. Exporter использует host network/PID,
технический порт 9100 и read-only файловые системы хоста. `privileged` и Docker
socket не используются. Сервер рассчитан на Linux с Docker Engine и доверенную LAN.

История за последние сутки хранится в именованном volume `history`
(у штатного Compose-проекта — `pc-monitor_history`). Обычный перезапуск её
сохраняет. `docker compose down -v` удаляет историю и для обычной остановки не нужен.

## Отказы

`/health` возвращает 200 при доступном Prometheus, успешном опросе exporter
и свежих базовых метриках; при отказе зависимости — 503.
Открытая вкладка обнаруживает тайм-ауты и потерю связи, отмечает значения
устаревшими, сохраняет раскладку и повторяет запросы. После восстановления
обновление возобновляется без перезагрузки страницы. Пропуски не выдаются за нули.
Первое открытие страницы при недоступном сервере требует работающего сервера.

## Проверка и границы поддержки

Во время разработки проверены сборка `docker build .`, запуск полного Compose,
сборка из копии исходников без локальных зависимостей, 4 теста API на Python 3.12,
Ruff и TypeScript/Vite. Набор Playwright содержит 45 сценариев для desktop,
планшетного и телефонного размеров: создание карточек, сохранение, обе темы,
полный экран, 24 карточки, масштабированное редактирование мышью и touch,
перенос старых настроек, отказы и восстановление. После последних изменений
отдельно повторены проверки автоматического применения размера поля.

Реальная остановка exporter дала 503 с последующим восстановлением 200.
Пауза изолированной копии приложения была обнаружена открытым клиентом;
после снятия паузы связь восстановилась без reload.

Команды воспроизведения — в [docs/testing.md](docs/testing.md).
Актуальный внешний результат сборки — в
[GitHub Actions](https://github.com/TopProHatsker/remote-monitoring/actions/workflows/ci.yml).
Локальные проверки не заменяют успешный CI опубликованного коммита.

Браузерные проверки выполнены в Chromium с эмуляцией размеров и touch.
Safari на физическом iPad пока не проверен. iPhone, антисон, TLS, PWA,
облачное размещение и поддержка физического Windows/macOS-хоста не входят
в текущую версию. Работа в Docker Desktop может измерять его Linux-VM.

## Основные файлы

- `Dockerfile`, `compose.yaml`, `monitoring/prometheus.yml` — сборка и окружение
- `app/main.py`, `app/metrics.py` — HTTP API, готовность и разрешённые запросы метрик
- `frontend/src/main.ts`, `frontend/src/style.css` — интерфейс, сетка и темы
- `tests/`, `frontend/tests/` — проверки API, контейнеров и браузерных сценариев
- `.github/workflows/ci.yml` — проверки, сборка и запуск на каждый push/PR

Учебная работа не отправлялась преподавателю. Публикация исходников
в GitHub не является сдачей работы в учебную систему.
